# Этап K2: параллельные задачи в отдельных копиях проекта (git worktree)

Цель: как в Codex и Claude Code. Пользователь ведёт несколько задач в одном проекте одновременно, и каждая идёт в своей копии (`git worktree`) со своей веткой. Готовое вливается в основную папку одной кнопкой, неудачное выбрасывается.

Параллельно работают этапы K3 (доступ с телефона) и K4 (автоматизации). Их файлы не трогай:
- `src/renderer/remote-access.tsx`, `src/renderer/automations.tsx`, `src/renderer/settings.tsx`, `src/renderer/chat.tsx`;
- `src/main/telegram*`, `src/main/remote*`, `src/main/schedules*`, `src/main/hooks*`.

В `src/main/index.ts` и `src/preload/index.ts` правь минимально: регистрацию IPC вынеси в функцию из нового `src/main/worktrees.ts` и вызови её одной строкой. Типы уже в `src/shared/api.ts`: `Worktree`, `WorktreeMerge`, `Conversation.worktree`, методы `worktree*`. Их не меняй.

## Внутренняя часть (`src/main/worktrees.ts`)
- **Git.**
  - Используем системный `git` (`execFile`, без shell).
  - Нет git — ошибка «Для параллельных задач нужен Git: git-scm.com/downloads».
  - Проект не репозиторий — ошибка с кодом `not-a-repo`. UI предложит «Включить git в проекте» (IPC `worktree:init-git(origin)`): `git init`, `git add -A`, `git commit -m "Начало"`, с `user.name`/`user.email` = vsemkod локально в репозитории, если глобальных нет.
- **`create(origin, title)`.**
  - Ветка `vsemkod/<slug>` от текущего `HEAD`: slug из названия латиницей (транслитерация кириллицы), до 40 символов, уникальный.
  - Папка `<данные приложения>/worktrees/<8 символов sha1(origin)>/<slug>`, `git worktree add -b`.
  - Если в исходной папке есть незакоммиченные изменения, верни в ответе `warning`: «Копия создана из последнего коммита — несохранённые в git правки остались только в основной папке». Для этого допиши необязательное поле в ответ IPC, тип в `api.ts` не меняй: renderer прочитает `warning` через узкое расширение.
  - Запиши `{ path, origin, branch, base }` в `<данные>/worktrees.json`.
- **`info(directory)`.**
  - `changed` — незакоммиченные изменения плюс файлы в `git diff --name-only base...branch`.
  - `ahead` — `git rev-list --count base..branch`.
- **`merge(directory, message)`.**
  - В копии: `git add -A`, `git commit -m message`, если есть изменения.
  - В исходной папке: если она грязная, ошибка «Сначала сохраните или отмените изменения в основной папке».
  - Затем `git merge --no-ff <branch> -m "<message>"`.
  - При конфликте: `git merge --abort` и `{ merged: false, conflicts: [...файлы], message }`.
  - После успеха копия остаётся, её можно удалить отдельно.
- **`remove(directory)`.** `git worktree remove --force` + `git branch -D` + запись из `worktrees.json`. Нельзя, пока в чате этой копии работает агент.
- **Чаты.**
  - При `chat:list(origin)` добавь чаты всех копий этого проекта. У чатов в копиях заполни `Conversation.worktree = { origin, branch }`.
  - Папки копий не должны попадать в список проектов (`projects`, `recentProjects`) и в «Недавние».
- **Пропавшая копия.** Удалена руками или папка исчезла — чат открывается только для чтения истории, `info` возвращает `null`.

## Интерфейс (дизайн — ровно так)
1. **Переключатель в поле ввода.**
   - Только для нового чата (домашний экран), если папка выбрана. Это чип в строке под полем ввода рядом с выбором папки: иконка ветки (добавь `branch` в `icons.tsx`: три кружка и линии, 16px, обводка как у остальных) и текст «Отдельная копия».
   - Включённый — мятная обводка и фон `var(--mint-hover)`.
   - Подсказка `title`: «Задача пойдёт в отдельной копии проекта: можно вести несколько задач параллельно и потом влить результат».
   - Состояние запоминается в `localStorage` для проекта.
   - При отправке первого сообщения: `worktreeCreate`, затем чат создаётся в папке копии, как обычный. Предупреждение `warning` показывается уведомлением.
   - Ошибка `not-a-repo` — уведомление с кнопкой «Включить git».
2. **Боковая панель (`chat-groups.tsx`).** Чаты копий лежат под своим проектом, как обычные. Перед названием — маленькая иконка ветки (12px, `var(--muted)`), во всплывающей подсказке — ветка.
3. **Шапка чата в копии.** Слева от инструментов шапки — чип `composer-control` «⑂ <ветка>» (ветку обрежь до 24 символов с …). По клику меню (`.model-panel`, как другие меню шапки):
   - «Влить в основную папку» с подписью «Изменено файлов: N». Неактивно, если `changed = 0` или агент работает.
   - «Открыть папку копии».
   - Разделитель.
   - «Удалить копию…» (`danger`). Подтверждение `window.confirm`: «Удалить копию и ветку <branch>? Невлитые изменения пропадут.»

   После влития — уведомление «Влито в основную папку» с кнопкой «Удалить копию». При конфликтах — уведомление `error` с текстом и кнопкой «Попросить агента разобраться». Она отправляет в этот чат: «Влей в эту ветку текущую основную ветку (`git merge <base>`), разреши конфликты в файлах: … и проверь, что всё работает».
4. Обе темы. Минимальная ширина окна — 900px.

## Проверки
- **Тесты (vitest)** на временном git-репозитории (`git init` в `os.tmpdir()`):
  - создание, `info`, влитие без конфликтов и с конфликтом (abort);
  - удаление, slug из кириллицы;
  - `not-a-repo`.
- **Живая проверка** через `playwright-core` `_electron` с временным `VSEMKOD_DEV_DATA` и временным проектом-репозиторием:
  - включить «Отдельная копия», отправить задачу бесплатной модели (Kilo без ключа) «создай файл hello.txt с текстом привет»;
  - проверить, что файл появился в копии, а не в основной папке;
  - влить и проверить, что файл появился в основной;
  - удалить копию;
  - скриншоты обеих тем: чип в поле ввода, меню в шапке, боковая панель. Не используй `setViewportSize`.
- **Команды:** `npm test`, `npm run typecheck`, `npm run build`.
- **Не коммить.** Если песочница не даёт писать в существующие файлы, сложи изменения в `app/stage-k2.patch` (`git diff --binary` от корня репозитория, с новыми файлами). Рабочую копию для проверок создавай в `%TEMP%`, **не внутри папки проекта**.
- **В конце кратко:** что сделано, что не получилось, результаты проверок.
