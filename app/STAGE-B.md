# Этап B — подключение провайдеров, свои подписки, настройки

Продолжаем `app/` (этап A сделан: см. `app/README.md`, `app/SPEC.md`). Дизайн — строго по `app/design/*` (графит + мятный, без эмодзи и «нейрослопа»). Весь UI на русском. Не раздувай код: переиспользуй существующие модули, без лишних абстракций.

## 1. OpenRouter — вход в один клик (oauth_pkce), по-настоящему
- Сверь протокол с актуальной документацией OpenRouter (OAuth PKCE): `authorizeUrl?callback_url=http://localhost:<port>/callback&code_challenge=<S256>&code_challenge_method=S256` в системном браузере → одноразовый локальный сервер ловит `code` (таймаут 5 минут, отдаёт в браузер аккуратную страницу «Готово, вернитесь в vsemkod») → `POST exchangeUrl` → ключ → KeyStore → провайдер «Подключён», его модели становятся доступны в роутере.
- Состояния в диалоге: «Откройте браузер и войдите» → «Ждём вход…» (с кнопкой «Отмена») → «Подключено» / понятная ошибка.

## 2. Подключение по ключу (manual_key) — мастер
- Кнопка «Открыть страницу ключей» (`keyPageUrl` в системном браузере) + поле «Вставь ключ».
- Переключатель «Поймать ключ из буфера обмена» (по умолчанию выкл., явное согласие): пока диалог открыт, не дольше 5 минут, проверяет буфер раз в секунду по `keyPattern` провайдера; при совпадении подставляет ключ и показывает «Нашли ключ». Буфер никуда не сохраняется и не логируется.
- Проверка ключа `GET {baseUrl}/models` → «Подключено» или «Ключ не подошёл».

## 3. «Свои подписки и ключи» — новый раздел подключения
Пользователь может подключить свои платные/бесплатные подписки и ключи — их модели показываются в меню отдельной группой **«Мои подписки»** (после бесплатных).
- **GitHub Copilot** — официальная интеграция. Сначала проверь, поддерживает ли встроенный OpenCode 2.4.1 Copilot нативно (провайдер `github-copilot` и его штатный device-flow вход). Если да — подключение через штатный механизм движка (адаптер: запуск auth-flow, показ кода устройства «Введите код XXXX-XXXX на github.com/login/device», кнопка «Открыть GitHub»). Если нет — не изобретай обход, пометь в отчёте.
- **ChatGPT Plus/Pro** — только через официальный «Sign in with ChatGPT» (OpenAI открыл его открытым приложениям). Проверь, поддерживает ли OpenCode 2.4.1 это нативно; если да — подключай штатно. Если для нашего приложения нужна отдельная регистрация (client id) — не подделывай чужой client id; сделай экран-заглушку и опиши в отчёте, что должен сделать владелец проекта.
- **API-ключи** (manual_key, кастомные провайдеры роутера, без каталога): OpenAI, Anthropic (только API-ключ), Google AI Studio, DeepSeek, Z.ai (в т.ч. эндпоинт coding plan), Moonshot/Kimi, MiniMax, Qwen/DashScope (международный), Groq, Mistral и **«Свой OpenAI-совместимый»** (базовый URL + ключ; список моделей — из `GET /models`). Данные провайдеров (базовые URL, формат API) сверь с их документацией. Для Anthropic-формата, если роутер умеет только OpenAI-формат, используй OpenAI-совместимый эндпоинт провайдера, если он есть, иначе подключай через нативный провайдер движка.
- **НЕ добавлять**: вход подпиской Claude Pro/Max (Anthropic запрещает сторонним приложениям) и Gemini CLI / Antigravity OAuth (Google запрещает). Никаких обходов.

## 4. Настройки (полноценная страница)
Подключённые провайдеры и подписки (статус, «Отключить» с удалением ключа), папка по умолчанию, «Автовыбор модели», «Ловить ключ из буфера», «Проверять обновления каталога», версия приложения, ссылки GitHub / vsemkod.ru.

## 5. Тосты и мелочи
- Тосты: «Переключился на GLM 5.3 — у Kimi кончилась квота» (событие роутера), «Новая раздача: … · Подключить» (из `changes.json`, только top), «Подключено: OpenRouter», понятные ошибки сети/квот. Аккуратные, в стиле макетов, автоисчезают.
- В диффе скрывать служебную строку «\ No newline at end of file».
- Меню моделей: если в каталоге есть модели с `tier: "new"` — группа «Новые» (свернутая, с пометкой «экспериментальные»).

## 6. OpenCode Zen (исследовать, по умолчанию ВЫКЛ)
У встроенного OpenCode есть свой провайдер Zen с бесплатными моделями («Free-tier chat models require OpenCode»). Наше приложение запускает настоящий движок OpenCode. Прочитай актуальные условия Zen/OpenCode и реши, разрешено ли это для стороннего GUI поверх официального движка. Реализуй поддержку за флагом `ENABLE_OPENCODE_ZEN_FREE` (по умолчанию `false`), без подделки идентификаторов клиента, и в отчёте процитируй найденные условия и свой вывод.

## Проверка (обязательно)
- Юнит-тесты: PKCE (генерация verifier/challenge, обработка callback, таймаут), детектор ключа в буфере (регэкспы, лимит времени, выключено по умолчанию), кастомный OpenAI-совместимый провайдер в роутере (мок-сервер), отключение провайдера удаляет ключ.
- `npm test`, `npm run typecheck`, `npm run build` проходят.
- Живой прогон: OAuth OpenRouter — до момента открытия браузера и запуска локального callback-сервера (сам вход требует пользователя — не пытайся логиниться); manual_key — с мок-сервером; Kilo-чат по-прежнему работает.
- Скриншоты новых экранов (подключение OAuth, мастер ключа, «Свои подписки», настройки, тост) в `app/screenshots/`, сравни с макетами и поправь.
