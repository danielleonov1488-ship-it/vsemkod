# Этап F — нижняя панель (скорость, кэш, контекст, лимиты и подписки) и чистка поля ввода

Продолжаем `app/` (этапы A–E применены). Дизайн задаёт владелец проекта и я (Claude) — **делай ровно как описано**, без самодеятельности в стиле; в спорных местах — минимально и аккуратно, в токенах `design/free-ai.css`, обе темы. Образец поведения — нижняя строка DeepSeek Harness: «219 ток/с · Попадание в кэш 99.8% · ◔ 64%», по клику на кружок — разбивка контекста.

## 1. Нижняя строка под полем ввода
Одна строка **под** блоком поля ввода (вне его рамки), по ширине поля, высота 24px, шрифт 12px, цвет вторичный, иконки 13px. Слева направо:
- `⚡ 42 ток/с` — скорость последнего ответа (выходные + рассуждения токены / время от первого токена до конца шага). Показывать после первого ответа в чате.
- `◎ Кэш 87%` — доля входных токенов из кэша провайдера за последний запрос: `cache.read / (input + cache.read)`. Скрыт, если провайдер кэш не сообщает.
- `◔ 6%` — кольцо заполнения контекста (то, что сейчас стоит в поле ввода, переезжает сюда).
- справа (прижат вправо): **индикатор лимитов** текущего провайдера: точка (мятная > 30% остатка, янтарная 10–30%, красная < 10%, серая — неизвестно) + текст, например `Kilo · 183 из 200 в час`, `OpenRouter · 37 из 50 сегодня`, `Groq · 940 из 1000 сегодня`, для подписок — `ChatGPT · по тарифу`.
- **Всплывающие подсказки** (свой компонент-тултип в стиле меню приложения, не системный `title`), появляются через 300 мс при наведении и при фокусе с клавиатуры:
  - скорость: «Скорость ответа: 42 токена в секунду. Первый токен пришёл через 1,2 с.»
  - кэш: «87% запроса взято из кэша провайдера — так быстрее и экономнее для квоты. Кэш держится, пока вы работаете с той же моделью.»
  - контекст: «6% окна модели занято: 12 тыс. из 200 тыс. токенов. Нажмите для подробностей.»
  - лимиты: «Бесплатная квота Kilo: 200 запросов в час с вашего IP. Сброс через 34 мин.»

## 2. Всплывающее окно «Контекст» (клик по кольцу)
Карточка над строкой (как меню моделей): заголовок «Контекст · 6%», справа «12 тыс. / 200 тыс.», полоса заполнения, ниже разбивка с цветными метками: «Системная подсказка», «Инструменты», «Сообщения» (если движок даёт такую разбивку; если нет — «Вход», «Выход», «Рассуждения», «Кэш (чтение/запись)»). Внизу кнопка «Сжать контекст» (то же, что `/compact`) и строка «Движок сам сжимает контекст, когда окно почти заполнено».

## 3. Всплывающее окно «Подписки и лимиты» (клик по индикатору лимитов)
Карточка шириной ~360px. Заголовок «Подписки и лимиты». Список всех подключённых провайдеров и подписок (бесплатные без входа — тоже, например Kilo): иконка/название, строка остатка с маленькой полосой («183 из 200 в час · сброс через 34 мин»), под ней мелко — условие из каталога (`freeLimits.note`). У каждой строки справа — меню «⋯» с «Отключить» (кроме Kilo) / «Открыть кабинет провайдера». Ниже разделитель и блок «Можно подключить» — 2–3 топовых провайдера из каталога с кнопкой «Подключить» (открывает существующий диалог подключения). Внизу ссылка «Все подключения в настройках». Ничего не меняется в логике подключения — только новый вход в неё.

## 4. Откуда брать цифры (main/router)
- Роутер уже проксирует ответы провайдеров: снимай заголовки лимитов с каждого ответа — `x-ratelimit-limit-requests`, `x-ratelimit-remaining-requests`, `x-ratelimit-reset-requests`, `x-ratelimit-limit-tokens`, `x-ratelimit-remaining-tokens`, а также `X-RateLimit-Limit/Remaining/Reset` (OpenRouter-стиль) — сохраняй последнее значение по провайдеру (в памяти + `usage.json`, без содержимого запросов).
- Если заголовков нет — локальный счётчик по окну из `freeLimits` каталога (rph — скользящий час, rpd — сутки по UTC) и честная подпись «по нашим подсчётам».
- OpenRouter: дополнительно `GET https://openrouter.ai/api/v1/key` с ключом пользователя (не чаще раза в 10 минут) — использованные кредиты/лимит, `is_free_tier`.
- Подписки через движок (ChatGPT, Copilot): если движок не даёт лимитов — «по тарифу» и ссылка на страницу использования у провайдера.
- Скорость: роутер замеряет время от первого байта до конца стрима и берёт `usage` из финального SSE-чанка (если провайдер прислал; движок может ставить `stream_options.include_usage`), либо считает в renderer по событиям `session.usage` и времени шага. Кэш — из `usage.cache.read`/`prompt_tokens_details.cached_tokens`.
- Новые данные — через существующий IPC (событие вроде `router:stats`), типы в `src/shared/api.ts`. Поле в `DesktopApi` сделай **необязательным**, чтобы веб-копия (`src/web/demo-api.ts`) не ломалась; в веб-копии покажи только скорость и контекст (если есть), индикатор лимитов — «Демо · N сообщений осталось».

## 5. Чистка поля ввода
- Имя модели в поле и в меню: убрать префикс производителя «NVIDIA: » и хвост « (free)», брать имя из каталога, если модель в нём есть (`Nemotron 3.5 Lightning`). Максимальная ширина имени 180px с многоточием.
- Выпадающий «По умолчанию / Низкий / Средний / Высокий» убрать из строки поля ввода. Уровень рассуждений — строка «Рассуждения: средне ›» внутри меню моделей (подменю), только если у модели есть варианты; в поле ввода — ничего, кроме имени модели.
- Чипы в нижней строке поля ввода (`+`, папка, режим доступа, микрофон, модель, отправить): одинаковая высота 28px, радиус 8px, отступы между ними 6px, ничего не наезжает; на узкой ширине имя папки сокращается первым.
