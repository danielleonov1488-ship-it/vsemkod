# Этап K4: задачи по расписанию и хуки после ответа агента

Цель:
1. «Каждое утро в 9:00 проверь зависимости» — vsemkod сам откроет чат в проекте, выполнит задачу и пришлёт уведомление.
2. «После каждой правки прогоняй тесты, а если упали — пусть агент чинит».

Параллельно работают этапы K2 (параллельные задачи) и K3 (доступ с телефона). Их файлы не трогай:
- `src/main/worktrees*`, `src/main/telegram*`, `src/main/remote*`;
- `src/renderer/remote-access.tsx`, `src/renderer/index.tsx`, `src/renderer/composer.tsx`, `src/renderer/chat-groups.tsx`.

Твой интерфейс:
- `src/renderer/automations.tsx` — заглушка уже подключена в «Настройки → Автоматизации», пропсы `directory`, `projects`, `onError`;
- одна строка статуса хука в `src/renderer/chat.tsx`;
- стили в конце `src/renderer/styles.css` с префиксом `.auto-`.

В `src/main/index.ts` и `src/preload/index.ts` правь минимально: регистрацию вынеси в функции новых файлов и вызови одной строкой. Типы уже в `src/shared/api.ts`: `Schedule`, `ScheduleWhen`, `ScheduleInput`, `Hook`, `HookInput`, событие чата `hook`, методы `schedules`/`saveSchedule`/`removeSchedule`/`runSchedule`/`hooks`/`saveHook`/`removeHook`. В `src/renderer/chat-state.ts` событие `hook` уже кладётся в `view.hook`. Типы не меняй.

## 1. Расписание (`src/main/schedules.ts`)
- **Хранение и проверка.** `<данные>/schedules.json`. Проверка раз в 30 с; `nextRun` по местному времени.
  - `daily`: время `HH:MM`, дни недели 1–7 (пусто = каждый день).
  - `interval`: каждые N часов, 1–168, от последнего запуска или от сохранения.
- **Запуск.**
  - Создать чат в `directory` с названием «<name> · 27 нояб., 09:00» и отправить `prompt` теми же функциями main, что и `chat:send`.
  - Модель — `model` или автовыбор, доступ — `access`. Разрешены только `read`, `edit`, `full`: «спрашивать» без человека зависнет, такой вариант при сохранении — ошибка.
  - Во время работы — значок в трее («агент работает»), как обычно.
  - По окончании: `lastRun` и системное уведомление «Готово: <name>» с открытием чата, как у обычных уведомлений (`announce`). Ошибка — уведомление с текстом.
- **Пропуски.**
  - Приложение было закрыто в момент запуска — при старте выполнить один пропущенный запуск, если он был не раньше 12 часов назад.
  - Тот же запуск ещё идёт — следующий пропускается.
- **«Запустить сейчас»** (`runSchedule`).
- **Проект пропал** — задача помечается ошибкой, не падает.

## 2. Хуки (`src/main/hooks.ts`)
- **Хранение.** `<данные>/hooks.json`. Хук без `directory` — для всех проектов.
- **Когда.** После завершения хода агента в чате (там, где main получает результат `send`, с `changes`), для каждого включённого хука этого проекта:
  - если `onlyWhenFilesChanged` и правок не было — пропуск;
  - иначе команда в папке чата через системную оболочку (`cmd /c` на Windows, `sh -c` на POSIX), таймаут 5 минут, без интерактива, хвост вывода 4 КБ.
- **События.** Событие чата `hook`: `running` → `passed`/`failed` (код и хвост вывода).
- **Если упала и `fixAttempts > 0`.** Отправить в тот же чат сообщение:

  > Команда `<command>` завершилась с ошибкой (код N):
  > ```
  > <хвост>
  > ```
  > Найди причину, исправь и проверь снова.

  Не больше `fixAttempts` раз подряд. Счётчик сбрасывается, когда команда прошла или пользователь сам написал сообщение.
- **Исключения.** Хуки не запускаются для чатов бокового окна и во время сжатия контекста.

## 3. Интерфейс `automations.tsx` (дизайн — ровно так)
**Группа «По расписанию»:**
- Список карточек: название; строка «Каждый день в 09:00 · Пн–Пт · проект <имя папки>»; «Следующий запуск: завтра в 09:00»; результат прошлого запуска (✓/✗ + время, ссылка «Открыть чат»). Справа переключатель «включено» и меню (`composer-control`): «Запустить сейчас», «Изменить», «Удалить».
- Кнопка `small-button` «Новая задача» открывает форму в карточке:
  - Название.
  - Проект — `select` из `projects`.
  - Что сделать — `textarea`.
  - Когда — сегмент «Каждый день» / «Каждые N часов».
    - Для «Каждый день»: время `<input type=time>` и дни недели — семь чипов Пн…Вс, по умолчанию все.
    - Для «Каждые N часов»: число 1–168.
  - Доступ — сегмент «Только чтение» / «Может править файлы» / «Полный доступ» с пояснением под ним для полного: «может запускать любые команды».
  - Кнопки «Сохранить» / «Отмена».
- Над формой три готовых шаблона-чипа, они заполняют поля:
  - «Утром проверять зависимости» — каждый день 09:00, только чтение: «Проверь зависимости проекта на устаревшие и уязвимые версии. Напиши короткий отчёт: что обновить и почему.»
  - «Вечерняя сводка» — 18:00 Пн–Пт, только чтение: «Посмотри изменения в проекте за сегодня (git log, git diff) и напиши короткую сводку на русском.»
  - «Еженедельно обновлять README» — каждые 168 часов, может править файлы: «Обнови README.md под текущее состояние проекта: что это, как запустить, структура.»
- Пусто — «Пока нет задач по расписанию. Задачи выполняются, пока vsemkod запущен (можно свёрнутым в трей).».

**Группа «Хуки после ответа агента»:**
- Карточки: название, команда моноширинно, «Проект: <имя> / Все проекты», «Только если менялись файлы», «Чинить ошибки: до N раз»; переключатель и меню «Изменить» / «Удалить»; последний результат (✓/✗, код, «Показать вывод» — раскрывает `pre` с хвостом).
- «Новый хук» — форма:
  - Название.
  - Команда.
  - Проект (`select`: «Все проекты» + `projects`).
  - Чекбокс «Только если агент менял файлы» (вкл. по умолчанию).
  - «Если команда упала — просить агента исправить» (число 0–5, по умолчанию 2).
- Шаблоны-чипы:
  - «Тесты» — `npm test`;
  - «Проверка типов» — `npx tsc --noEmit`;
  - «Сборка» — `npm run build`;
  - «Линтер» — `npm run lint`.

**Строка в чате (`chat.tsx`).** Под последним ответом агента, если есть `view.hook` (проброс пропа из `index.tsx` запрещён — используй уже существующие пропсы `Chat`). Если пропса нет, добавь один необязательный проп `hook` и опиши в итоге, какую строку Claude добавит в `index.tsx`.
- Вид: маленькая строка с иконкой: «Хук «<name>»: <command> — выполняется…» / «прошёл» (мятный) / «упал, код N» (красный) + «Показать вывод».

Обе темы.

## Проверки
- **Тесты (vitest):**
  - `nextRun` для `daily` с днями недели и для `interval`;
  - пропущенный запуск в пределах 12 часов;
  - запрет `access: "ask"`;
  - хук: пропуск без правок, `failed` → сообщение агенту, лимит `fixAttempts`, сброс счётчика;
  - таймаут команды.
- **Живая проверка** через `playwright-core` `_electron` (временный `VSEMKOD_DEV_DATA`, временный проект, Kilo без ключа):
  - задача «интервал» с `runSchedule` → чат создан, ответ пришёл, `lastRun.ok`;
  - хук `node -e "process.exit(1)"` с `fixAttempts: 1` → агенту ушло сообщение об ошибке;
  - скриншоты раздела в обеих темах. Не используй `setViewportSize`.
- **Команды:** `npm test`, `npm run typecheck`, `npm run build`.
- **Не коммить.** Если песочница не даёт писать в существующие файлы, сложи изменения в `app/stage-k4.patch` (`git diff --binary` от корня, с новыми файлами). Рабочую копию для проверок создавай в `%TEMP%`, **не внутри папки проекта**.
- **В конце кратко:** что сделано, что не получилось, результаты проверок.
