# vsemkod app — спецификация v0.1

Десктоп-приложение для AI-кодинга (как Claude Code desktop): боковая панель с чатами, чат с агентом, поле ввода с выбором модели снизу. Агент читает и правит файлы в выбранной папке и запускает команды. Модели — только бесплатные раздачи из каталога `https://vsemkod.ru/catalog.json` (схема: `../catalog-bot/src/schema.ts`). Каждый пользователь работает на **своих** бесплатных квотах; у vsemkod нет серверов и аккаунтов.

Утверждённый дизайн: `app/design/*.html` + `free-ai.css` + скриншоты `app/design/png/` (графит + мятный `#3DDC97`, бренд «vsem» + мятное «kod», бегемотик `../brand/logo.svg`). Повторяй его максимально близко. Никаких эмодзи и «нейрослопа» в UI. Весь интерфейс — на русском.

## Архитектура
```
Electron main ─┬─ CatalogService     — загрузка/кэш каталога, changes → уведомления «Новая раздача»
               ├─ KeyStore           — ключи провайдеров, шифрование через electron.safeStorage, файл в userData
               ├─ Router (localhost) — OpenAI-совместимый прокси: модель vsemkod → провайдеры → фолбэк
               ├─ ConnectService     — подключение провайдеров (none / oauth_pkce / manual_key)
               ├─ EngineService      — запуск и управление встроенным движком OpenCode (headless server)
               └─ IPC (contextBridge, типизированный)
Renderer (React + TS + Vite) — экраны по макетам
```
- Стек: **Electron (актуальный стабильный) + electron-vite + React + TypeScript**, стили — обычный CSS по токенам из `design/free-ai.css` (без Tailwind). Тесты — vitest. Безопасность Electron: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, строгий CSP, все внешние ссылки — через `shell.openExternal` только для http(s).
- Установка зависимостей с локальными кэшами (песочница): `npm install --cache ./.npm-cache`, переменные `ELECTRON_CACHE=./.electron-cache`, `ELECTRON_BUILDER_CACHE=./.eb-cache` (добавь в `.npmrc`/скрипты и в `.gitignore`).

### Router (главная наша логика) — `src/main/router/`
- Локальный HTTP-сервер на `127.0.0.1:<свободный порт>`, OpenAI-совместимые эндпоинты `GET /v1/models` и `POST /v1/chat/completions` (включая `stream: true` SSE и tool calls — прозрачная пересылка). Доступ только с localhost + случайный bearer-токен, который знает только движок.
- Модели роутера — канонические id из каталога (`kimi-k3.1-pro`, `glm-5.3`, …) + специальная `auto`.
- Для запроса к модели M: кандидаты = активные `offers` модели M, у чьих провайдеров есть доступ (auth `none` или сохранённый ключ). Порядок: сначала провайдер, к которому «приклеена» текущая сессия (кэш промптов), затем по `rank`/здоровью. Подставляет `providerModelId` и ключ, шлёт на `provider.baseUrl`.
- Фолбэк: при 429/5xx/таймауте до первого байта ответа → следующий провайдер той же модели; провайдер уходит в «охлаждение» (уважать `Retry-After`, иначе экспоненциально от 30 с). Если провайдеров модели не осталось и включён «Автовыбор» (или запрошена `auto`) → следующая модель по `rank` среди tier `top`, затем `good`; в ответ добавляется заголовок/событие, чтобы UI показал «Переключился на GLM 5.3 — у Kimi кончилась квота». После начала стрима переключение не делаем.
- Учёт: счётчики запросов/ошибок по провайдеру в памяти + персистентно в userData (без содержимого запросов).
- Юнит-тесты на выбор кандидатов, охлаждение, автовыбор, стрим-проксирование (мок-провайдеры).

### EngineService — встроенный OpenCode
- Движок агента — **OpenCode** (MIT): https://github.com/sst/opencode (или актуальный адрес), режим headless-сервера (`opencode serve`) + официальный SDK (`@opencode-ai/sdk` или актуальное имя). **Сначала изучи актуальную документацию и закрепи точную версию** (в 2026 вышел 2.x с изменённым API) — оберни SDK в свой адаптер `src/main/engine/adapter.ts`, чтобы UI не зависел от деталей.
- Бинарник OpenCode кладём в приложение (extraResources по платформам) — разберись, как он распространяется (npm-пакет с платформенными бинарниками / GitHub releases), и сделай скрипт `scripts/fetch-engine.(mjs|ts)`, скачивающий нужную версию с проверкой sha256.
- Конфиг движка генерируем сами (временный файл / переменная окружения): единственный провайдер `vsemkod` (OpenAI-compatible) с `baseURL` = наш Router и моделями из каталога; отключить все остальные провайдеры, телеметрию/шаринг, автообновление движка. Данные движка — в userData приложения.
- Возможности для UI через адаптер: список сессий (чатов) по проекту, создать сессию в папке, отправить сообщение с выбранной моделью, поток событий (текст, вызовы инструментов: чтение/правка файла с диффом, команда), запросы разрешений (правка файла / команда) → UI спрашивает «Разрешить / Разрешить всегда в этом чате / Запретить», отмена.
- Папка проекта: по умолчанию `Документы/vsemkod Projects` (создать), выбор — системный диалог.

### ConnectService — подключение провайдеров
- `none` (Kilo): доступен сразу.
- `oauth_pkce` (OpenRouter): открыть системный браузер на `authorizeUrl?callback_url=http://localhost:<port>/callback&code_challenge=<S256>&code_challenge_method=S256`, поймать `code` локальным одноразовым сервером, `POST exchangeUrl {code, code_verifier, code_challenge_method}` → ключ → KeyStore. Сверь протокол с актуальной докой OpenRouter.
- `manual_key`: открыть `keyPageUrl` в браузере; в окне подключения поле «Вставь ключ» + переключатель «Поймать ключ из буфера обмена» (по `keyPattern`, только пока окно открыто, максимум 5 минут, с явным согласием). Проверка ключа: `GET {baseUrl}/models` с ключом.
- Отключение провайдера и удаление ключа — в настройках.

### CatalogService
- Загрузка `https://vsemkod.ru/catalog.json` → запасной `https://raw.githubusercontent.com/danielleonov1488-ship-it/vsemkod/main/catalog-bot/data/catalog.json` → кэш в userData → встроенная копия каталога в ресурсах (на случай первого запуска без сети). Валидация zod-схемой (скопируй схему из `../catalog-bot/src/schema.ts` в `src/shared/catalog-schema.ts`). Обновление каждые 30 мин.
- `changes.json` → тост «Новая раздача: Kimi K3.1 Pro бесплатно у Numes · Подключить» (только события про модели tier top).

## UI (renderer) — по макетам
1. **Первый запуск / новый чат** (`design/01-home.html`): «Чем займёмся?», большое поле ввода, чип папки (по умолчанию выбрана), селектор модели, подсказки.
2. **Чат** (`02-chat.html`): сообщения, компактные строки действий агента (прочитал / создал / изменил с раскрываемым диффом / запустил команду), запросы разрешений инлайн, стриминг текста, кнопка «Стоп».
3. **Меню моделей** (`03-models.html`): из поля ввода вверх; группы «Подключены» и «Бесплатно — подключить в один клик» (кнопка «Подключить»), «бесплатно до …» для акций, переключатель «Автовыбор». Показывать только tier top (+ «Показать ещё» для good).
4. **Подключение** (`04-connect.html`): диалог для провайдера (кнопка «Продолжить с Google/GitHub» для oauth, шаги для manual_key, статусы «Ждём вход в браузере…», «Подключено»).
5. **Настройки** (простая страница): подключённые провайдеры (отключить), папка по умолчанию, автовыбор, «Ловить ключ из буфера», версия, ссылка на GitHub.
6. Тосты: «Переключился на …», «Новая раздача …», ошибки сети/квот понятным русским языком.
