# vsemkod · этап D2

Десктопное приложение для работы с кодом через бесплатные модели из каталога vsemkod, свои подписки и API-ключи. Kilo Gateway работает без ключа. Чаты, настройки и диффы хранятся на компьютере. Агент отправляет выбранному провайдеру сообщения и контекст инструментов, необходимый для ответа.

## Запуск

Установите Node.js 24 LTS и запустите из папки `app/`.

```sh
npm install --cache ./.npm-cache
npm run dev
```

`postinstall` устанавливает Electron 45.5.0 и скачивает OpenCode 2.4.1 для текущей платформы. Скрипт сверяет архив с SHA-256 из закреплённого релиза. Бинарники и кэши остаются в `app/`. Для отдельной загрузки движка используйте `npm run fetch:engine`. Для другой цели передайте платформу и архитектуру, например `npm run fetch:engine -- --platform darwin --arch arm64`. [Релиз OpenCode 2.4.1](https://github.com/anomalyco/opencode/releases/tag/v2.4.1)

При первом запуске приложение создаёт `Документы/vsemkod Projects`. Добавить папку можно через «+» в списке проектов, а переключить проект — через чип папки в композере. Добавленные папки сохраняются даже без чатов. Основную папку можно изменить в настройках. При работающем агенте доступна кнопка «Стоп».

## Подключение моделей

- **OpenRouter.** Откройте «Настройки» → «Модели и подключения» и нажмите «Подключить» рядом с OpenRouter. Войдите в системном браузере. Одноразовый сервер на localhost ждёт ответ до пяти минут. Вернувшись в приложение, выберите модель каталога. [OAuth PKCE OpenRouter](https://openrouter.ai/docs/guides/overview/auth/oauth)
- **GitHub Copilot и ChatGPT Plus / Pro.** В «Своих подписках и ключах» доступны штатные подключения OpenCode 2.4.1. Для Copilot выберите «Открыть GitHub» и введите код устройства. Для ChatGPT подтвердите использование своего плана в браузере. Движок регистрирует собственный клиент при первом входе и хранит данные подключения в выделенном локальном профиле. [Copilot в OpenCode 2.4.1](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/github-copilot.ts), [Sign in with ChatGPT в OpenCode 2.4.1](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/chatgpt.ts), [документация OpenAI](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)
- **API-ключи.** Вставьте ключ в мастере. Приложение проверит его запросом `GET /models`. Для своего OpenAI-совместимого сервера укажите полный базовый URL, например `https://example.com/v1`. Для localhost доступен HTTP. Подхват из буфера по умолчанию выключен. Если включить его в мастере или настройках, программа проверяет буфер до пяти минут в открытом мастере и подставляет первое совпадение с форматом ключа.
- **Выбор модели.** Подключённые модели подписок и личных ключей находятся в группе «Мои подписки». Автовыбор переключает бесплатные модели каталога. Группа «Новые» появляется при наличии экспериментальных моделей и открывается отдельно.
- **Отключение.** В настройках кнопка «Отключить» удаляет локальный ключ или данные штатного подключения движка и убирает соответствующие модели из меню. Там же можно изменить папку, автовыбор и проверку каталога.

### OpenCode Zen

Флаг `ENABLE_OPENCODE_ZEN_FREE=true` включает бесплатные чат-модели Zen. По умолчанию флаг выключен. Условие Zen сформулировано так — “Free-tier chat models require OpenCode; use paid models or Go from other clients.” [Условия доступа к бесплатным моделям](https://opencode.ai/docs/console/models/#endpoints)

Документация OpenCode допускает собственный интерфейс поверх штатного сервера и встраивание движка. По этим документам vsemkod может использовать бесплатный Zen через официальный OpenCode 2.4.1. Движок выполняет запрос через свой провайдер со своими заголовками, а vsemkod управляет сессией через SDK. Приложение показывает только модели с нулевой ценой входных и выходных токенов. [Интеграция с OpenCode](https://opencode.ai/docs/build), [условия OpenCode](https://opencode.ai/legal/terms-of-service), [реализация в движке](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/opencode.ts)

## Этап D

- В «Общих» настройках доступны тёмная, светлая и системная темы, три размера шрифта, папка и режим доступа по умолчанию, поведение Enter, уведомления и запрет сна на время ответа.
- В композере Shift+Tab переключает режим доступа. «Только чтение» использует агента `plan`, «Авто-правки» разрешают запись в рабочую папку, «Спрашивать» требует подтверждения правок и команд. «Полный доступ» требует подтверждения при первом включении. Enter ставит сообщение в очередь, Ctrl+Enter прерывает текущий ответ, два нажатия Esc останавливают агента.
- В меню «+» композера можно прикрепить файлы, упомянуть файл через `@` или открыть список команд `/`. Файлы и изображения можно также перетащить или вставить из буфера. Для изображений нужна модель с поддержкой этого формата. `@` ищет файлы и папки проекта, `/` открывает команды и навыки OpenCode. `/export` сохраняет чат в Markdown, `/compact` запрашивает сжатие контекста.
- Чаты сгруппированы по папкам. Ctrl+K переводит фокус в поиск. Из меню чата можно переименовать, закрепить, форкнуть, архивировать или удалить чат. «Откатить сюда» и «Вернуть» используют границу сообщения OpenCode. Для Git движок восстанавливает файлы из снимков, для папок без Git приложение восстанавливает текстовые правки по сохранённым диффам инструментов.
- Ctrl+B открывает правую панель, Ctrl+J — терминал проекта. В панели доступны диффы с отменой изменения файла, дерево проекта и терминал OpenCode. Команды агента видны на отдельной вкладке терминала.
- Настройки агента, MCP и навыков открываются в отдельных разделах. Глобальные правила сохраняются в `opencode/config/opencode/AGENTS.md` в папке данных. Для конкретного проекта положите `AGENTS.md` в его корне. Пользовательские команды можно разместить в `opencode/config/opencode/commands/`, навыки — в `opencode/config/opencode/skills/`. Список моделей своего сервера обновляется запросом `GET /models`. Для каждой выбранной модели можно задать контекст и максимальный вывод.

## Этап D2

- В чате видны таймер, поступающие рассуждения и ответ, вызовы инструментов и диффы. Когда агент заканчивает, ход сворачивается в строку с длительностью и числом действий. Статус отображается в шапке и рядом с чатом в списке.
- После 20 секунд без токенов чат предлагает сменить модель. После 120 секунд движок останавливает запрос, и чат предлагает повторить его. Ожидание разрешения, ответа на вопрос или завершения инструмента исключается из этого отсчёта. Выбор модели во время ответа применяется к следующему сообщению или повтору.
- При первом запуске выбирается быстрый вариант каталога с активной бесплатной раздачей без ключа и поддержкой инструментов. Во встроенном каталоге первым подходит Nemotron 3.5 Lightning. На бесплатном маршруте роутер ждёт первый байт до 45 секунд, после чего пробует другое предложение. При включённом автовыборе он может сменить модель. Ответ Kilo 429 ставит провайдера на паузу согласно `Retry-After`. Среднее время до первого байта видно в меню моделей после первого замера. В `usage.json` сохраняются только счётчики и время по модели и провайдеру.
- OpenCode работает с выделенным профилем vsemkod. Встроенный движок загружает навыки из `opencode/config/opencode/skills/` в папке данных и `.opencode/skills/` выбранного проекта. [Параметры OpenCode 2.4.1](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/cli/src/server-process.ts)

## Как устроено

- **Electron main** загружает и валидирует каталог, обновляет его каждые 30 минут и держит локальный кэш. В ресурсах есть копия для первого запуска без сети. API-ключи хранит `KeyStore` через системное шифрование Electron.
- **Router** слушает `127.0.0.1` на свободном порту и требует случайный bearer-токен. Он передаёт SSE и вызовы инструментов. При сбое до первого байта пробует другие бесплатные предложения, а при включённом автовыборе также другие бесплатные модели каталога. Для личного ключа запрос направляется выбранному провайдеру. Статистика хранится без содержимого запросов.
- **EngineService** запускает OpenCode 2.4.1 в режиме `serve` с локальной аутентификацией. Адаптер использует `@opencode/client` 2.4.1 для чатов, разрешений и штатных подписок. Подтверждения «всегда» сохраняются для конкретного чата. Правки текстовых файлов отображаются и в папках без Git. [Документация клиента OpenCode](https://opencode.ai/docs/build/client/)
- **React** рисует интерфейс по макетам из `design/`. Renderer общается с Electron через типизированный IPC. Внешние ссылки HTTP и HTTPS открывает системный браузер.

## Проверки

```sh
npm test
npm run typecheck
npm run build
npm run test:live
node scripts/verify-stage-b.mjs
```

Для `test:live` нужны интернет и доступная анонимная квота Kilo. Скрипт проверяет SSE через Router, затем запускает реальную сессию OpenCode. Агент создаёт `hello.txt` со словом «привет». Скрипт проверяет разрешения и дифф. Каждый запуск использует отдельную директорию в `.vsemkod-dev/`.

Скриншоты лежат в [screenshots](./screenshots). `verify-stage-b.mjs` запускает собранное приложение с отдельным профилем, проверяет запуск браузера и callback OpenRouter до входа пользователя, подключение ключа к локальному мок-серверу и удаление ключа. Для повтора проверки интерфейса этапа A запустите `npm run dev -- --remoteDebuggingPort 9417` с переменной `VSEMKOD_DEV_DATA`, указывающей на пустой каталог внутри `app/`, затем выполните `node scripts/verify-ui.mjs 9417`.

В среде проверки Windows Electron 45.5.0 остановился на проверке прав доступа к файлам, а DPAPI был недоступен. Снимки и сквозной сценарий этапа B получены в диагностическом Electron 44.0.0 с тестовым хранилищем ключей в памяти. Эти опции доступны только скрипту проверки. Живой прогон Kilo создал `hello.txt` с разрешением и диффом. Нативный Zen с включённым флагом ответил через Big Pickle. Запуск Copilot вернул код устройства, а OpenCode подготовил официальный вход ChatGPT с динамической регистрацией.

## Сборка установщиков

Из `app/` выполните `npm ci --cache ./.npm-cache` и запустите команду для своей ОС. Сборка обновит встроенный каталог из `catalog-bot/data/catalog.json`, если этот снимок новее и добавит OpenCode нужной архитектуры в ресурсы приложения. Файлы появятся в `app/dist/`.

| ОС | Команда | Файлы |
| --- | --- | --- |
| Windows | `npm run dist:win` | `vsemkod-windows-x64.exe`, `win-unpacked/` |
| macOS | `npm run dist:mac` | `vsemkod-macos-arm64.dmg`, `vsemkod-macos-x64.dmg` |
| Linux | `npm run dist:linux` | `vsemkod-linux-x64.AppImage` |

Установщик Windows создаёт ярлык на рабочем столе и устанавливает приложение в профиль пользователя без прав администратора и выбора папки. Сборки Windows и macOS распространяются без подписи, а macOS также без нотариального заверения Apple. Если файл скачан из официального релиза и предупреждение появилось при запуске, используйте штатные действия системы.

- **Windows SmartScreen.** В окне «Система Windows защитила ваш компьютер» нажмите «Подробнее», затем «Выполнить в любом случае», если эта кнопка доступна. [Microsoft Learn](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation)
- **macOS Gatekeeper.** Перетащите `vsemkod` из DMG в «Программы» и попробуйте открыть. Затем откройте «Системные настройки» → «Конфиденциальность и безопасность», нажмите «Всё равно открыть» и подтвердите. Для Apple Silicon скачайте `arm64`, для Intel — `x64`. [Поддержка Apple](https://support.apple.com/ru-ru/102445)
- **Linux.** Дайте AppImage право на запуск командой `chmod +x vsemkod-linux-x64.AppImage` и запускайте его из папки, в которую можете записывать обновления.

## Релиз и автообновления

1. Сверьте версию в `app/package.json` и `app/package-lock.json`. Поставьте и отправьте соответствующий тег, например `git tag v0.1.0` и `git push origin v0.1.0`. Для ручного запуска на том же теге используйте `gh workflow run release.yml --ref v0.1.0`. [Документация GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch)
2. Дождитесь завершения всех трёх сборок в Actions. Electron Builder загрузит четыре установщика, `latest.yml`, `latest-mac.yml`, `latest-linux.yml` и файлы `.blockmap` в черновик GitHub Releases. Карта блоков Linux встроена в AppImage.
3. Откройте черновик, проверьте вложения и нажмите **Publish release**. После публикации установщики доступны по постоянным ссылкам `releases/latest/download/<имя файла>`. [GitHub Releases](https://github.com/danielleonov1488-ship-it/vsemkod/releases)

Приложение проверяет опубликованный релиз при запуске и каждые 6 часов. В настройках доступна кнопка «Проверить обновления». Windows и Linux AppImage загружают обновление в фоне и предлагают перезапустить приложение. На macOS кнопка «Скачать» открывает последнюю версию в GitHub Releases. В dev-режиме проверка отключена.
