# Этап K3: доступ с телефона — веб-интерфейс в локальной сети и Telegram-бот

Цель: продолжить работу с телефона.
1. Открыть vsemkod в браузере телефона в той же Wi-Fi-сети по QR-коду.
2. Писать агенту через своего Telegram-бота откуда угодно.

Параллельно работают этапы K2 (параллельные задачи) и K4 (автоматизации). Их файлы не трогай:
- `src/main/worktrees*`, `src/main/schedules*`, `src/main/hooks*`;
- `src/renderer/automations.tsx`, `src/renderer/index.tsx`, `src/renderer/composer.tsx`, `src/renderer/chat-groups.tsx`, `src/renderer/chat.tsx`.

Твой интерфейс — только `src/renderer/remote-access.tsx` (заглушка уже подключена в «Настройки → Доступ с телефона», пропсы `projects`, `onError`) и стили в конце `src/renderer/styles.css`.

В `src/main/index.ts` и `src/preload/index.ts` правь минимально: регистрацию вынеси в функции новых файлов и вызови одной строкой. Типы уже в `src/shared/api.ts`: `RemoteAccess`, `remoteAccess`, `setRemoteWeb`, `setTelegramBot`, `onRemoteAccess`. Их не меняй.

## 1. Веб-доступ в локальной сети (`src/main/remote-web.ts`)
- **Что отдаём.** Движок OpenCode уже работает на `127.0.0.1` с авторизацией (см. `src/main/engine/service.ts`). Выясни, отдаёт ли сервер OpenCode 2.4.1 свой веб-интерфейс (как `opencode web`). Если да, проксируй его:
  - HTTP-прокси на Node `http` слушает `0.0.0.0:47800` (если занят — следующий свободный до 47820);
  - добавляет авторизацию движка;
  - поддерживает SSE и WebSocket (`upgrade`).
- **Если веб-интерфейса нет.** Запусти отдельный процесс `opencode web` из того же бинарника с тем же конфигом и папкой данных, на `127.0.0.1`, и проксируй его. Опиши выбранный путь в итоге.
- **Доступ.**
  - Пароль — 24 символа из `randomBytes` base64url, новый при каждом включении.
  - Вход по ссылке `http://<ip>:<порт>/?key=<пароль>`: прокси ставит cookie `vsemkod_key` (HttpOnly, SameSite=Lax) и делает редирект на `/`.
  - Без cookie или с неверным ключом — страница «Нет доступа. Отсканируйте QR-код в vsemkod → Настройки → Доступ с телефона.» и код 401.
  - Ограничь перебор: после 10 неверных попыток с одного IP — пауза 10 минут.
- **Адреса.** `urls` — все не-internal IPv4 интерфейсы (`os.networkInterfaces()`), в начале — частные сети 192.168/10/172.16–31.
- **Состояние.** Выключено по умолчанию и выключается при выходе из приложения. Включённость не запоминается.
- **Межсетевой экран Windows.** Он спросит разрешение — напиши об этом в интерфейсе.

## 2. Telegram-бот (`src/main/telegram-bot.ts`)
- **Подключение.**
  - Токен от @BotFather. Проверка — `getMe`. Хранение — зашифрованный `KeyStore` под отдельным id.
  - Запросы к `https://api.telegram.org/bot<token>/...` через `fetch`, long polling `getUpdates` (timeout 30). Повтор с паузой при ошибках сети.
  - Токен не попадает в логи.
- **Привязка.**
  - В приложении показывается 6-значный код (`pairCode`). Пользователь отправляет боту `/start <код>`. Первый такой чат становится владельцем (`pairedUser` = имя или @username).
  - Остальным бот отвечает «Это личный бот vsemkod» и игнорирует.
  - После привязки код не показывается. Кнопка «Отвязать» сбрасывает владельца и выдаёт новый код.
- **Работа.** Используй те же функции main, что и `chat:send`/`chat:create`/`chat:stop`/ответы на разрешения: вынеси общие куски в функции, не дублируй логику.
  - Текст → в текущий чат бота. Если его нет — новый чат в выбранном проекте (`project`, по умолчанию папка из настроек), название — первые слова сообщения.
  - Пока агент работает — `sendChatAction typing` раз в 4 с.
  - Ответ — итоговый текст агента: markdown упрощается до обычного текста, длинный режется на части по 3500 символов. В конце — строка «Изменено файлов: N», если были правки.
  - **Разрешения** — сообщение с inline-кнопками «Разрешить один раз» / «Разрешить всегда» / «Запретить» (`callback_query` → ответ на разрешение).
  - **Вопросы агента** — кнопки вариантов.
  - **Команды** (зарегистрируй через `setMyCommands`, описания по-русски):
    - `/new` — новый чат;
    - `/stop` — остановить агента;
    - `/project` — выбрать проект кнопками из списка проектов;
    - `/status` — что сейчас делает агент;
    - `/help`.
  - Модель — как в приложении по умолчанию (автовыбор), доступ — «Спрашивать».
- **Видимость.** Чаты бота видны в приложении как обычные чаты (их можно продолжить на компьютере).

## 3. Интерфейс `remote-access.tsx` (дизайн — ровно так)
Две группы `settings-group`.

**«Браузер телефона»:**
- Переключатель (как `PreferenceSwitch`) «Открыть доступ в локальной сети» с пояснением «Телефон должен быть в той же Wi-Fi-сети. Windows может спросить разрешение для сети — нажмите «Разрешить».».
- Когда включено — карточка: слева QR-код 168×168 на белом фоне со скруглением 10px и полем 10px; справа:
  - адрес крупным моноширинным (первый из `urls`) и кнопка «Копировать ссылку»;
  - остальные адреса мелко;
  - строка «Ссылка содержит ключ доступа — не пересылайте её»;
  - кнопка «Новый ключ» (выключить и включить).
- QR генерируй в renderer библиотекой с лицензией MIT: `qrcode` или `qrcode-generator`. Добавь в зависимости и `THIRD_PARTY_NOTICES.md`.

**«Telegram-бот»:**
- **Не подключён:** три шага нумерованным списком:
  1. «Откройте @BotFather в Telegram и создайте бота командой /newbot» с кнопкой «Открыть @BotFather» (`https://t.me/BotFather`);
  2. «Вставьте токен бота»: поле `password` и кнопка «Подключить»;
  3. «Отправьте боту код».
- **Подключён, не привязан:** «Бот @name подключён. Отправьте ему: /start 123456» (код крупно, кнопка копирования) и ссылка «Открыть бота» (`https://t.me/<name>`).
- **Привязан:** «Бот @name · владелец <user>», выбор проекта для новых чатов (`select` из `projects`), кнопки «Отвязать» и «Отключить бота».
- **Ошибки** — красным под группой.
- Состояние обновляется через `onRemoteAccess`. Обе темы, стили — в конце `styles.css` с префиксом `.remote-`.

## Проверки
- **Тесты (vitest):**
  - прокси: без cookie 401, `?key=` ставит cookie и редиректит, перебор блокируется, `upgrade` проксируется;
  - бот: разбор `update`, привязка по коду, чужой пользователь игнорируется, нарезка длинного ответа, `callback_query` для разрешений. Поддельный Telegram API — локальный HTTP-сервер, базовый URL сделай настраиваемым для тестов.
- **Живая проверка:**
  - включить веб-доступ в собранном приложении (`playwright-core` `_electron`, временный `VSEMKOD_DEV_DATA`);
  - открыть ссылку из `urls` вторым окном Electron/Chromium, убедиться, что виден интерфейс OpenCode и список чатов;
  - без ключа — 401;
  - бот — на поддельном API: сообщение → ответ бесплатной модели (Kilo) пришёл в `sendMessage`;
  - скриншоты раздела в обеих темах. Не используй `setViewportSize`.
- **Команды:** `npm test`, `npm run typecheck`, `npm run build`.
- **Не коммить.** Если песочница не даёт писать в существующие файлы, сложи изменения в `app/stage-k3.patch` (`git diff --binary` от корня, с новыми файлами). Рабочую копию для проверок создавай в `%TEMP%`, **не внутри папки проекта**.
- **В конце кратко:** что сделано, что не получилось, результаты проверок.
