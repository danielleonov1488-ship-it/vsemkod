# Этап G: параллельные чаты, файлы в чате, удобный выбор модели, режимы доступа, скорость

Продолжаем `app/`, этапы A–F уже применены. Отзыв владельца на релиз v0.1.0:
- пока агент работает, полприложения неактивно;
- агент не показывает файлы в чате;
- список моделей неудобный;
- скорость в токенах в секунду нигде не видна;
- режимы доступа непонятные;
- «+» у проектов работает плохо.

Дизайн задаю я (Claude). **Делай ровно как описано.** Где спорно, делай минимально, в токенах `design/free-ai.css`, обе темы. Образцы поведения: Claude Code desktop и Codex desktop.

## 1. Параллельные чаты (главное)
**Сейчас.** Флаг `busy` в `renderer/index.tsx` отключает «Новый чат», логотип и все строки проектов и чатов (`ChatGroups disabled`). В `main/engine/service.ts` стоит один `active` («Агент уже отвечает в другом запросе.»), один `stopRequested`, один `approvals`, а у роутера один `setTurn`.

**Нужно.** Агент отвечает в фоне, а пользователь в это время свободно переключается между чатами, открывает новый чат и запускает там ещё одного агента.
- **Main.** Состояние хода хранится по `sessionId`: `Map` для active/stop/approvals/pendingPermissions; у роутера `turns: Map<sessionId, {auto}>`, `lastRoutes` уже по сессии.
  - Не больше **3 одновременных ходов**. Четвёртый ждёт в очереди со статусом «В очереди».
  - `stop(sessionId)` останавливает только свой чат.
  - Разрешения и вопросы привязаны к своему чату.
  - Повторная отправка в чат, который уже отвечает, запрещена: то же поведение, что сейчас.
- **Renderer.** Вместо глобального `busy` заведи `running: Record<sessionId, ChatStatus>`.
  - События `onChat` для неактивного чата не теряются. Части, прогресс, usage и разрешения копятся в кэше по `sessionId`, и при возврате в чат он отображается актуальным, без перезагрузки истории посреди хода.
  - Поле ввода и кнопка «Стоп» относятся к открытому чату.
  - В боковой панели у каждого работающего чата крутится точка «работает» (уже есть `chat-status-dot`, `data-status="working"`). Если ждёт разрешения, точка янтарная, подпись «Ждёт ответа».
  - Когда фоновый чат закончил, точка становится мятной («Готово»), пока чат не откроют. Если окно не в фокусе, приходит системное уведомление (настройка `notifications` уже есть).
- **Блокировать** можно только то, что действительно ломается: смену проекта у **открытого** работающего чата и удаление или архивацию работающего чата (пункт меню неактивен, подсказка «Сначала остановите агента»). Всё остальное всегда активно.

## 2. Проекты в боковой панели
Механика как в Codex и Claude desktop:
- **Клик по строке проекта** (шеврон, папка, имя) сворачивает или разворачивает его. Новый чат он **не** создаёт. Выбранный проект подсвечен, как сейчас.
- **Справа в строке проекта** при наведении или фокусе появляются две иконки 24×24:
  - `+` с подсказкой «Новый чат в {имя}». Создаёт пустой чат в этом проекте, ставит фокус в поле ввода и разворачивает проект.
  - `⋯` с меню: «Новый чат», «Открыть в проводнике» (Finder или Files по ОС, через `shell.openPath` на папку), «Убрать из списка» (только из `projects.json`, файлы не трогать; если в проекте работает чат — неактивно).
- **Шапка «Проекты»:** `+` открывает выбор папки (как сейчас). Если папка уже в списке, просто выбрать и развернуть её.
- **«Новый чат» сверху** создаёт чат в текущем выбранном проекте.
- Если в проекте нет чатов, под ним одна строка `subtle` «Нет чатов».

## 3. Файлы и ссылки в ответе
**Сейчас** агент пишет «`G:\vsemkod\pelican-bicycle.svg`» обычным текстом. Нужно как в Claude Code.

1. **Ссылки на файлы.** В `AgentText` распознавай пути как в `inlineCode`, так и в обычном тексте:
   - абсолютные Windows или POSIX;
   - относительные с расширением, например `src/app.tsx` или `index.html`;
   - необязательный `:строка`.

   Чип показываем, **только если файл существует** внутри открытого проекта: проверка через новый IPC `file:stat(directory, path)` с кэшем по пути на время хода. Чип: высота 22px, радиус 6px, фон `--raised`, иконка файла 13px, имя файла. Каталог показываем `subtle`, только если он не корень проекта. При наведении показываем полный путь.

   Клик открывает правую панель на новой вкладке «Просмотр» с этим файлом. Правый клик или меню `⋯` даёт «Открыть в приложении», «Показать в папке», «Копировать путь».
2. **Карточки файлов под ответом.** После финального текста хода, над «Копировать / Повторить», выводим блок «Файлы» с файлами, которые агент **создал или изменил за этот ход** (данные есть в diff-трекере и частях tool).
   - Каждая карточка: иконка по типу, имя, `+N −M` (как в «Изменениях»), кнопки «Открыть» и «Показать в папке».
   - **Изображения** (png, jpg, jpeg, gif, webp, svg) рисуем превью прямо в карточке: максимум 360×240, `object-fit: contain`, фон-шахматка для прозрачности. Клик открывает «Просмотр».
   - **HTML** получает кнопку «Открыть в браузере» (`shell.openExternal(pathToFileURL)`).
   - Больше 4 файлов: показываем 4 и кнопку «Ещё N».
3. **Вкладка «Просмотр»** в правой панели (рядом с «Изменения / Файлы / Терминал»):
   - изображения — превью с подгонкой;
   - SVG — превью и переключатель «Код»;
   - текст и код — моноширинный вид с номерами строк, прокрутка к `:строка`;
   - сверху путь и кнопки «Открыть в приложении», «Показать в папке».
4. **Безопасность.** Новый IPC `file:preview(directory, path)`:
   - только файлы **внутри** проекта, `realpath` без выхода наружу;
   - изображения отдаём data URL, не больше 8 МБ;
   - текст — первые 512 КБ;
   - SVG показываем **только** через `<img src="data:image/svg+xml;base64,…">`, никогда не вставляем в DOM.

   «Открыть в приложении» (`shell.openPath`) **запрещено** для исполняемых и скриптовых файлов (exe, bat, cmd, ps1, sh, com, msi, scr, js, vbs, jar, app, lnk, desktop, AppImage). Для них «Открыть» заменяем на «Показать в папке».
5. **Ссылки.** Голые URL в тексте становятся ссылками (gfm autolink уже должен работать — проверь). `http(s)` открываем во внешнем браузере, как сейчас.

## 4. Режим доступа: меню вместо цикла
Чип «Спрашивать» в поле ввода сейчас по клику циклит режимы и показывает системный `window.confirm`. Нужно меню, как у Claude Code.
- **По клику** открывается меню над чипом, ширина 320px, стиль `model-panel`. Четыре пункта: иконка 16px, название 13.5px, ниже описание 12px `muted`, справа галочка у текущего.
  - **Только чтение** (иконка глаз): «Читает файлы и отвечает. Ничего не меняет и не запускает».
  - **Спрашивать** (иконка щит, по умолчанию): «Спросит перед каждой правкой и командой».
  - **Авто-правки** (иконка карандаш): «Сам правит файлы проекта. Команды — с вашего разрешения».
  - **Полный доступ** (иконка молния, цвет `--error`): «Правит и запускает команды без вопросов, в том числе за пределами проекта».
- **Подтверждение.** Первый выбор «Полного доступа» не включает режим сразу. Пункт раскрывается внутри меню в предупреждение (фон danger-tint, радиус 8px):
  - текст: «Агент сможет удалять файлы и выполнять любые команды без подтверждения. Включайте только в проекте, которому доверяете, и с сохранённой копией (git)»;
  - кнопки «Включить» (danger) и «Отмена».
  - После «Включить» сохраняем `fullAccessConfirmed`. Убери `window.confirm` и в `index.tsx`, и в настройках: там такое же встроенное подтверждение.
- **Низ меню:** строка `subtle` «Shift+Tab — следующий режим». Shift+Tab продолжает циклить, но на «Полный доступ» без подтверждения не переходит: перескакивает и открывает меню с раскрытым предупреждением.
- **Чип:** иконка режима, название и шеврон. В режиме «Полный доступ» текст и иконка `--error`.

**Нужно.**

  - `ток/с` берём **измеренный** у нас по этой модели и провайдеру (п. 8, среднее последних 5 ответов). Если замеров нет — `speed` из benchmarks.json со знаком `~`. Если нет ничего, не показываем.
  - Нынешнее время до первого ответа («~1,2 с») уходит в подсказку.

## 6. Полный список моделей у подключённых провайдеров
Для каталожных провайдеров с ключом пользователя (Numes, OpenRouter, Groq, ModelScope, Runcrate, Z.ai, NVIDIA и т. п.):
- Раз в 6 часов и при подключении запрашиваем `GET {baseUrl}/models` с ключом и берём только бесплатные модели:
  - для OpenRouter — `pricing.prompt == "0"` и `pricing.completion == "0"` или суффикс `:free`;
  - для провайдеров, где весь free-план бесплатный (Numes free, Groq, ModelScope, Kilo free), — все модели с поддержкой tools, если провайдер это сообщает.
- Модели, которых нет в каталоге, показываем в «Ещё модели» с именем провайдера. Маршрутизируем как личные модели (механизм `personal` в роутере уже есть).
- Кэш в `provider-models.json`, без ключей.

## 7. benchmarks.json (данные готовит бот, приложение читает)
Новый файл рядом с каталогом: `https://vsemkod.ru/benchmarks.json`, зеркало — `.../catalog-bot/data/benchmarks.json`, плюс копия в `resources/` при сборке (как `catalog.json`). Схема:
```json
{ "schemaVersion": 1, "generatedAt": "ISO", "source": { "name": "Artificial Analysis", "url": "https://artificialanalysis.ai/", "indexVersion": "5.0" },
  "models": { "<catalog modelId>": { "index": 62.1, "speed": 180.4, "ttft": 0.52 } } }
```
- Схема в `shared/` — **не strict** по неизвестным полям.
- Файла нет или он битый — живём без индекса.
- `catalog.json` **не трогать**: его схема strict, и v0.1.0 сломается.

## 8. Скорость (ток/с) должна быть видна всегда
**Сейчас** у Numes в строке под полем нет ни скорости, ни кэша. Провайдер не присылает `usage` в стриме, поэтому `tokens.output = 0` и `replySpeed` возвращает `undefined`.
- **Роутер.** Если `body.stream === true` и нет `stream_options`, добавляй `stream_options: { include_usage: true }`. Если провайдер ответил 400 и в тексте ошибки есть `stream_options`, повтори без него и запомни провайдера (в памяти).
- **Запасной вариант.** Если `usage` всё равно не пришёл, считай токены по потоку: текст плюс рассуждения, оценка `ceil(символы / 3.5)` для латиницы и `ceil(символы / 2.2)` для кириллицы. В строке тогда показываем `≈ 85 ток/с`, а в подсказке: «Провайдер не сообщил точное число токенов — оценка по тексту».
- **Хранение.** Скорость считается по каждому шагу и хранится по модели и провайдеру в `usage.json` (последние 5 замеров, без содержимого). Отсюда берёт скорость выбор модели.
- **В строке под полем:**
  - скорость **последнего ответа** этого чата;
  - если её ещё нет (новый чат), бледная средняя скорость выбранной модели с подсказкой «Обычно {N} ток/с у этой модели»;
  - во время ответа скорость обновляется вживую, раз в секунду, по токенам с первого токена.
