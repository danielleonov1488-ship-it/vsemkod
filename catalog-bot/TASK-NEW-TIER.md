# Бот-каталог: tier «new» для новых моделей + радар стелс-моделей OpenCode Zen

Контекст: `README.md`, `SPEC.md`, код в `src/`. Код компактный, без лишних абстракций, по-русски в сообщениях и описаниях.

## 1. Tier `new` — новые бесплатные модели, которых нет в реестре
Сейчас бесплатная модель из структурных источников (OpenRouter, Kilo, Numes), не найденная в `registry/models.ts`, уходит в `candidates` и в приложении не видна. Нужно:
- Добавить `"new"` в `tierSchema` бота (в приложении `app/src/shared/catalog-schema.ts` он уже есть: `["top","good","new","basic"]` — порядок и значения должны совпасть; приложение не трогать).
- Если наблюдение пришло из **структурного** источника, модель не сопоставлена с реестром, поддерживает **tools** и контекст **≥ 128k**, — создавать автоматическую модель: `id` = нормализованный slug (`modelSlug`), `name` — из имени провайдера, если есть в ответе API (иначе красиво из slug), `vendor` — из префикса id (`xiaomi/...` → «Xiaomi», неизвестно → «Неизвестно»), `tier: "new"`, `description`: «Новая бесплатная модель. Мало проверена — может работать нестабильно.», `capabilities` — по данным API (`tools`, `reasoning`, `vision`, если есть), `rank` — после всех моделей реестра. Её предложение — обычный `offer` (status active, confidence structured).
- Модели-«утилиты» не брать: эмбеддинги, модерация, rerank, только аудио/картинки, роутеры (`openrouter/free`, `kilo-auto/free`), размер < 20B, если он явно указан в id.
- Если такая модель позже появилась в реестре — используется запись реестра (без дублей). Если предложений не осталось — модель удаляется из каталога вместе с ними (по существующим правилам `OFFER_MISSING_RUNS`/retention).
- Событие в `changes.json`: существующий тип `offer_added` с понятным текстом «Новая модель: X бесплатно у Y». Новых типов событий не вводить (приложение строго валидирует схему).

## 2. Радар OpenCode Zen (стелс-модели)
У OpenCode Zen публичный список моделей без ключа: `GET https://opencode.ai/zen/v1/models` (ответ OpenAI-подобный, у моделей есть `id`, `name`, `description`, `limit.context`, `capabilities.tools.supported`, `cost.text.input.price`/`output.price`, `release_date`). Бесплатные (`price` 0 или id с `-free`) — то, что OpenCode раздаёт внутри своего клиента; там появляются стелс-модели (например, недавно мелькнула `hungerg-free`).
- В каталог (`catalog.json`) Zen **не добавлять** (его нельзя вызывать напрямую из роутера, приложение использует Zen только через встроенный движок OpenCode за флагом).
- Писать отдельный файл `data/radar.json`: `{ schemaVersion: 1, generatedAt, models: [{ source: "opencode-zen", id, name, description, contextWindow, tools, free: true, firstSeen, lastSeen, active }] }` — сортировка стабильная, без лишних коммитов, если ничего не изменилось (как у остальных данных).
- Когда появляется новая бесплатная модель Zen, которой не было, — сообщение в Telegram (если заданы `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`, механизм уже есть) «Радар: в OpenCode Zen появилась бесплатная модель X». Пропавшие — `active: false`, удаляются через 30 дней.
- Workflow `.github/workflows/catalog.yml` должен коммитить и `data/radar.json` (добавь в `git add`).
- Сайт и приложение не трогать.

## Проверка
- Тесты vitest: автосоздание модели `new` (с tools и 128k — да; без tools / 32k / эмбеддинг / роутер — нет; совпадение с реестром — запись реестра), удаление при исчезновении, парсер Zen (на фикстуре ответа), стабильность `radar.json`.
- `npm test`, `npm run validate` проходят. Живой прогон `npm run update -- --no-llm` (или аналог без LLM, если есть флаг; иначе только структурные источники) — покажи, какие модели стали `new` и что попало в `radar.json`. Ключ LLM из `.env` не печатать.
- Обнови `README.md`/`SPEC.md` кратко.
