# Лендинг vsemkod.ru

Статический сайт на GitHub Pages. Для публикации достаточно HTML, CSS и ES-модулей. Каталог и журнал изменений попадают в корень сайта из `catalog-bot/data/` при сборке Pages.

- `index.html` — первый экран с HTML-окном vsemkod, каталог, три шага, лента возможностей, открытый код и FAQ.
- `styles.css` — светлая и тёмная палитры, адаптив, анимации и режим `prefers-reduced-motion`. На светлом фоне дополнительный оттенок `#0D754A` сохраняет контраст мелкого зелёного текста.
- `app.js` — настройки демо и релиза, переключатель темы, навигация, каталог и лента карточек. В `localStorage` хранится только выбранная тема.
- `demo.js` — сценарий автопоказа, Turnstile по фокусу, сессия, SSE, безопасный Markdown и очистка переписки. В API уходит до восьми последних сообщений. Переписка удаляется из памяти вкладки по кнопке или через 10 минут после последнего сообщения.
- `assets/app-*.webp` — сжатые скриншоты приложения для ленты возможностей.

## Локальная проверка

Из корня репозитория запусти `node site/dev/mock-demo-api.mjs` и открой `http://127.0.0.1:4173`. Сервер читает снимок каталога из репозитория и включает демо с публичным тестовым ключом Cloudflare. Установка зависимостей не нужна. [Тестовые ключи Turnstile](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

- `--static` запускает сайт с исходной конфигурацией. При пустом `DEMO_API` доступен только автопоказ.
- `MOCK_PORT`, `MOCK_REMAINING` и `MOCK_CLOSED=1` задают порт, лимит сессии и исчерпанную дневную квоту.
- Сообщения `:xss`, `:auth`, `:busy` и `:slow` проверяют экранирование, обновление сессии, временную ошибку и остановку ответа.

Для рабочего демо укажи базовый URL воркера в `DEMO_API` и публичный ключ невидимого виджета в `TURNSTILE_SITEKEY` в начале `app.js`. Воркера и проверку токенов на сервере описывает протокол в `SITE-V2.md`.

Папка `dev/` исключена из публикации. [Скриншоты проверки](dev/screenshots/README.md).
